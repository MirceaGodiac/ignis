# Weight-space programming: what the evidence shows, and what IGNIS took from it

Compiled 13 November 2026. Three sourced dossiers sit behind this synthesis, with file-level
citations and verbatim excerpts: [MIT artifacts](research/mit_wsp.md),
[the Legora post](research/legora.md), [replications and related work](research/related_work.md).
Statements below are marked **read** (seen in a released artifact), **author-reported**, or
**unverifiable**.

## 1. What MIT demonstrated

Source: "Weight-Space Programming", Takehi, Teoh, Zhang, Khattab (MIT CSAIL), published 2 Nov 2026,
https://rikiyat.github.io/blog/weight-space-programming/ ; logs under CC BY 4.0 at
https://github.com/RikiyaT/lm_understand-logs (8,097 files).

The authoring model in every experiment is "Astra" (OpenAI `gpt-6-astra`) run through the Codex CLI
with its tools switched off (**read**: harness config and per-call `run.json`).

| Exp. | What was done | Protocol | Result |
|---|---|---|---|
| 4 | Repair of one failing car-on-ramp PPO policy | One reply, no tools, no forward pass. 51 statements; 6,073 of 171,664 weights changed (**read**) | 1,024 of 1,024 test episodes succeed (**read**); the scene is nearly deterministic |
| 5 | MinAtar policies (Breakout, Seaquest, Asterix) written into an all-zero network | One reply per game, no tools, no feedback; given the rules and the game source. 637–815 nonzero of 20,486 weights (**read**) | 517.4 / 53.1 / 53.2 against 25.3 / 88.9 / 55.2 for the best PPO seed (**read**); Breakout is probably capped by the episode limit |
| 6 | A 1.48 M-weight Go network (MLP 243 → 512×6 → 82) | Weights written by **Python loops** in a sandbox; 0, 10, 25 or 50 forward-pass "budgets" with game records as feedback | About 54 % wins against hidden PPO nets with 0 passes, 84 % / 81 % with 50 (**author-reported**, eval files **read**) |
| 8 | A looping fault of Qwen3.5-0.8B on maths removed | Python kernel plus up to 50 forward passes; the edit is `W = W0 − 6·outer(u, mask·(u@W0))`, strength chosen by trial | MATH-500 7.9 % → 48.1 %; the same recipe failed on Gemma 3 270M (**author-reported**) |

What matters for us:

- **Only experiments 4 and 5 are literal hand-writing.** Experiment 6 is weights generated by code
  the model wrote, with feedback; experiment 8 is a formula edit tuned with forward passes.
- **The edit language** is NumPy-style assignment into named tensors: `W[i,j] = v`, ranges and
  strides, literal lists, `*=`, `+=`, `-=`, `ZERO T`; statements apply in order (**read**).
- **Every hand-built function is linear, piecewise-linear or a threshold.** Steep steps
  `tanh(80·x − 80·knot)`, ±1 logic combined with weights of ±10 and a bias that selects AND / NAND,
  hinge ramps `relu(total − 18)`, signed values carried as two ReLUs, large-M gating. No artifact
  hand-builds an exponential, a logarithm, a power or a product of two continuous inputs (**read**).
- Graded signals use small weights (0.01–0.2), logic 6–20, steps 80, gates 200–1,000. Hand-written
  nets are 2–4 % dense.

## 2. What Legora's CTO demonstrated, and what cannot be checked

Source: Jacob Lauritzen, https://x.com/jacsebl/status/2117606206764175543 (3 Nov 2026), three posts
and one table image.

**Read in the post:** "Got fable to hand-write weights of a 100k param model to recognize real versus
fake legal citations… Basically one-shotted a full NN that's better than training it."

**Author-reported (table image only):**

| Weights | Labels seen | Nonzero | Test accuracy |
|---|---|---|---|
| Hand-written | 0 | 3,793 | 97.8 % |
| Hand-written, one revision | 5,062 | 3,828 | 98.9 % |
| Trained | 512 / 5,062 / 8,192 | 107,745 | 76.5 % / 92.9 % / 94.6 % |

So 97.8 % is before the revision and 98.9 % after it.

**Not disclosed anywhere, hence unverifiable:** the architecture, whether the numbers were typed or
produced by code, which rules the network encodes, the dataset and its split, whether the test set
was kept from the model, and what feedback the revision used. No code, weights, prompt or data were
published, and he answered none of the replies that asked.

**Not reproductions of his experiment:**

- FluidInference CiteNet (https://huggingface.co/FluidInference/citenet-coreml): another network
  (397,250 parameters, 13,871 nonzero); Claude wrote a rule specification **and the code that compiles
  it into weights**; it flags citations that cannot exist, not plausible inventions.
- Paul Calcraft's thread (https://x.com/paul_cal/status/2118072016670732400): his own similar
  experiment and a critique — such a net works "when there is a ruleset it can follow" and decompiles
  to plain Python with identical decisions.

## 3. Replications and critiques of the MIT work

- **flecart** (Huang, "I Tried to Break Weight Programming", 3 Nov 2026,
  https://github.com/flecart/weight-programming, **read**): the released networks reproduce their
  scores; the Breakout net is a compiled short program (a 10-line Python player with the same
  algorithm scores 534); where no short program exists the hand-written net loses to PPO (Seaquest).
  Claude Opus 5.5 also writes working nets one-shot for some games and fails on others.
- Follow-up preprints (abstracts only, **not verified in full**): results are uneven across tasks
  (arXiv:2611.09382, 2611.08647); on physically interpretable parameters it works and it falls to
  chance above about 30 opaque weights (2611.11537); one-shot medical-imaging nets reach AUC 0.72
  against 0.83 for the same CNN trained on 256 labels (2611.12066).

## 4. Four things that are not the same

| | How the numbers came to be | What it can support | Examples |
|---|---|---|---|
| 1 | Literal numbers chosen by the model | "The model compiled what it knew into weights" — to be compared with what that knowledge alone achieves | MIT exp. 4–5; IGNIS **W0** |
| 2 | A program written by the model generates them | Code generation | MIT exp. 6; CiteNet; Tracr |
| 3 | Conventional training directed by a model | Credit belongs to the optimizer and the data | LLM-SR; IGNIS fitted baselines |
| 4 | Direct edits after looking at development feedback | Optimisation with a human-like optimizer: needs an untouched test set and a count of looks | MIT exp. 6 with passes, exp. 8; IGNIS **W1, W2** |

A mixed case takes the highest row it touches.

## 5. What transfers to scientific models

1. **Zero network = the physical law.** A skip path carries the linear law; hidden units only add
   hinges the author placed. Editing a working baseline succeeds far more often than writing from
   nothing (APHYNITY, ReZero, grey-box models).
2. **Piecewise-linear in a log or normalised space; smooth physics in the fixed forward.** The MIT
   artifacts contain no hand-built smooth nonlinearity, so we do not ask for one: the network
   outputs `ln K`, `ln η`, `ln λ`; the exponential, the ODE and the integral are structural code.
3. **Fixed O(1) inputs with physical knots** (Arora et al. 2018 for exact ReLU representation of
   piecewise-linear functions; LeCun 1998 on input scale). A hinge at "air", at "2.4 mm", at "20 s"
   is a statement a reader can check.
4. **Hazards as log-linear predictors over a baseline shape** (Prentice & Gloeckler; Nnet-survival).
5. **Local state from declared finite differences**, never from a request-time fit.

## 6. Where it worked and where it failed in IGNIS

Full numbers: [RESULTS.md](RESULTS.md). All on development partitions; the test partition is untouched.

- **FLEX, zero-shot (W0): it worked.** 316 numbers written from the d²-law, B-number scaling and
  radiative-loss reasoning, before any run. Validation CRPS 50 µm against 137 µm and 103 µm for the
  two fitted D² baselines. The hand-written rate law is within 5–10 % of the observed mid-burn rates.
  Here physics identifies the parameters, and the fitted baselines are structurally poorer (no
  extinction, constant rate).
- **ACME, zero-shot: it did not.** The time scales depend on the flame-size regime and on the
  operators' protocol; neither is derivable from first principles at the needed precision. W0 loses
  to a constant-hazard baseline.
- **Hand revision overfits like any optimizer.** FLEX W1 improved train (62 → 44 µm) and worsened
  validation (50 → 56 µm) because of one interaction read off three or four runs. ACME normal W1 and
  W2 improved train and lost to W0 on validation for extinction. ACME inverse W1 improved both and
  reached the fitted linear baseline, still behind the full fitted model.
- **BASS: nothing can be claimed.** No run has a metric calibration.

We do not claim that weight-space programming is better than training. On this evidence it is
useful exactly where prior physics is strong and data are few, and it needs the same held-out
discipline as training the moment the author looks at data.

## 7. Architecture decisions for IGNIS

- New specs instead of the legacy parameterisations: `flex-wsp-v1`, `acme_normal-wsp-v1`,
  `acme_inverse-wsp-v1`, `bass-wsp-v1`. The legacy FLEX and BASS forecasts estimate local latents at
  request time (Newton/Laplace, L-BFGS, least squares); the WSP crate does not link that code.
- One hidden ReLU layer with a linear skip per quantity, every hidden unit with a named role.
- FLEX: extinction as an intensity **per unit of burn progress**, so where the flame goes out is
  decided by how much has burned; the forecast is the unconditional mixture (still burning, or
  extinguished earlier), because the evaluator scores every post-cutoff diameter.
- ACME: two cause-specific log-hazards; operator termination is its own cause and its own row.
- BASS: a diagonal operator on four cosine modes with a unit guard instead of the 5,825-weight
  cosine operator, whose locals need a request-time MAP.
- Uncertainty is declared `assumed_noise` everywhere. Nothing is called a posterior.

## 11.2 Rules that stay

1. Every weight is typed by the author model. A script may measure, score and report sensitivities;
   it never writes a weight.
2. A candidate and its adoption rule are committed before its score on unseen data exists.
3. New data is scored blind first, once, and only then studied. Groups are frozen before outcomes
   are read. Media is measured by an agent that sees no forecast.
4. `holdout/` and `runs/dev/holdout_ext/` are not opened and `--final-test` is not passed until the
   one final run at the end, on frozen releases, returning aggregates only.
5. Each candidate is named zero-shot or data-informed, each number carries its origin class.

## 11.3 The revision method ("typed back-propagation"), as asked by the owner

The analogue of a training step, with the author in place of the optimiser:

1. **Forward.** Run the frozen release on the study cases (train groups only); keep the loss of every case.
2. **Decompose.** Loss by session, regime, horizon; bias against spread (is the centre wrong or the band).
3. **Attribute.** A script perturbs each physical block of numbers by a stated small step and reports
   how each case's loss moves. This says which numbers *can* explain which errors. It writes nothing.
4. **Reason and type.** The author moves a number only when (a) the error pattern holds across several
   independent sessions, not one test; (b) the new value stays inside the range its sources allow;
   (c) the step is damped (about half of what the attribution suggests); (d) it is typed to two or
   three significant figures; (e) a physical reason is written beside it. An error no number can
   explain inside its allowed range is a missing mechanism: that is a new forward, not a patch.
5. **One step per new batch of data.** An epoch is new independent data, never another pass over the
   same cases. The next unseen batch is the check on the step.

Everything written this way is **data-informed**.

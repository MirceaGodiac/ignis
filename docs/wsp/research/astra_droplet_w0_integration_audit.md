# Integration audit: frozen property-droplet numerical W0

Date: 2026-11-14. Scope: engineering audit only, with synthetic checks. No NASA data, development or evaluation outcomes, held groups, or dossier feedback were read for this audit. The independent numerical author recorded zero-shot/no-feedback exposure in the envelope; this audit does not independently establish that historical exposure. There is no registered release or qualified NASA forecast here.

## Decision and blocking invariant

**The frozen JSON deserializes as `ModelSpec`, but is not a valid `ModelSpec` under the actual Rust validator.** `geometry.pi` has bounds `[3.141592653589793, 3.141592653589793]`; `ModelSpec::validate` requires `min < max` and returns `ModelSpec: geometry.pi: empty bounds` (`crates/ignis-core/src/contracts/wsp.rs`, `ModelSpec::validate`). The scalar shape `[]` itself is supported and its single `set` assignment is syntactically valid. `HandwrittenWeightPatch::validate_against` calls `spec.validate()` first; consequently `assemble::materialize` rejects the frozen inputs before constructing tensors. JSON parse or a generated-schema check is not the semantic validation.

The owning Rust canonicalization (`ModelSpec::spec_hash` -> `Digest::of_json`, recursively sorted canonical JSON) returns **`sha256:15bd54f7610888b9c5b243ac99322630e58c2e4a498789ef9137bc1c205921b8`** for the frozen spec, despite its invalidity. It is distinct from SHA-256 of `spec.json` bytes. The envelope is `PatchMeta` plus a `schema_version` field, not itself a `HandwrittenWeightPatch`; the coordinator must create the patch with `assemble::make_patch`, preserving the author/exposure metadata and unchanged literal operations, using that Rust spec hash. This does not cure the failed validation.

The minimally invasive way to preserve **all frozen spec, op, and kernel bytes and their identity** is for the contract owner to decide whether equal tensor bounds legitimately denote a singleton and, if accepted, change the shared `ModelSpec` invariant to allow `min == max`, with backwards-compatibility and boundary tests across consumers. That is a shared contract change requiring the normal owner/review process; this audit does not make or authorize it. Keep inverted bounds rejected and keep patch values inside bounds. No assembly may pretend the existing invariant already permits equality. If the owner declines, the alternative is a separately identified and versioned spec whose bounds change (e.g. omitted bounds), with an explicit supersession/provenance record and its own canonical hash; retain the original files intact. It is a new specification, not the frozen spec assembled unchanged. Changing a patch, claiming the file-byte digest as the canonical hash, widening bounds silently, or substituting a target name is not a fix.

A controlled hypothetical clone with only the bounds removed, **in memory**, had hash `sha256:03d629cfdd9417bb577dfe0724781cd7056ff6e9ecfa6d011688d5a0c807ee19`. Its original literal ops materialized to the exact binary64 π and an isolated synthetic registry roundtrip worked. The cloned spec is not the frozen spec, no real forward/strict fixture check ran for that roundtrip, and its synthetic release record is not a registered scientific release.

## What exists and what it means

- `property_droplet_w0.rs` defines its own `Material`, `State`, `Environment`, `Transport`, `Numerics`, `Provenance`, `Supplied`, and `Literals`; it is a standalone kernel, not serialized shared wire types. `evaluate` returns an equivalent-volume **liquid diameter**, plus species rates, energy and mass diagnostics, and explicit unavailable optical and chemical outputs. `advance` takes a caller-supplied positive step and applies explicit Euler; it refuses depletion/phase/domain crossings and does not itself provide an arbitrary-horizon event forecast.
- `isothermal_reference` is a pure-liquid, constant-condition, externally thermostatted quiescent reference. `flame_sheet_reference` assumes an already existing infinite-rate sheet, pure fuel, no ambient fuel, unity Lewis number, no radiation and zero gravity/imposed velocity. It returns conditional initial reaction-sheet radius/temperature and a liquid-diameter reference. It neither establishes a flame nor predicts finite-rate ignition, extinction, luminosity, or visibility. The current `Quantity` enum supports `liquid_diameter`, `visible_flame_diameter`, and `uv_flame_diameter`, but has **no reaction-sheet-radius quantity**. Never label a reaction sheet as a visible or UV flame or an ignition/extinction forecast. A physical limit law, even one returning diameter or depletion under assumptions, is not by itself a usable fire-safety forecast for the 19 investigations; qualification and independent evidence remain future work.
- `physical_core.rs` is separately exposed by `ignis-wsp/src/lib.rs`; the frozen droplet file is not exposed there and does not import that core. These modules have distinct provenance, finite, property, domain and vector types. `physical_core::SuppliedProperty` covers only molar mass and gas heat capacities, with phase/reference semantics, whereas the kernel additionally needs liquid density/cp, latent heat, saturation pressure, gas transport and more. The core's `GasMixture` normalizes supplied fractions inside a caller tolerance; the droplet kernel requires keyed explicit ambient fractions and does not normalize them. Do not force conversions or treat these APIs as interchangeable; an adapter must preserve every source/locator, SI/raw value, property phase, reference convention, declared domain, frame and dependency, and explicitly justify any normalization and derived values. Unavailable or nonrepresentable inputs must refuse, not become zero. Kernel state inventories are `f64` with a shared initial-state provenance rather than per-value `Measured`; a cross-lane consumer needs an explicit provenance-preserving binding.
- `PrefixBundle` contains `known_conditions: BTreeMap<String, Measured>`, controls and observations, not a typed component property/transport inventory or a complete mapping into this kernel. `Measured` has raw/SI values, evidence, locator and derivation, but arbitrary labels in a feature's `source` or `structured_identity@1` do not implement that mapping. Never infer fuel properties from a name, pull post-cutoff observations, or manufacture missing closures. `ForecastRequest` admits a stored run/prefix by host-controlled service, not an untrusted input scope. A structured input contract and producer/consumer agreement are necessary for a genuine cross-lane route; without it a private synthetic/reference library test is the appropriate boundary.

## Assembly and runtime path, after the contract decision

1. Preserve and rehash the frozen files. Validate with the **actual** `ModelSpec::validate`, create the patch via `assemble::make_patch` from `author-envelope.json` and `literal-ops.json`, and call `patch.validate_against` / `assemble::materialize` with no parent. Verify the scalar value and shape bit-for-bit, complete assignment, non-finites, duplicate/unknown ops and out-of-bounds refusal. The kernel independently requires π to equal `std::f64::consts::PI`. Record canonical spec/patch hashes and input byte hashes separately.
2. Only after an authorized consumer and contract exist, expose `property_droplet_w0` in `crates/ignis-wsp/src/lib.rs`. A new adapter owned by the WSP lane should bind the tensor from `LoadedRelease` rather than hard-code π; verify `spec.check_release`, the manifest forward hash and actual tensor before calling `evaluate` or `advance`. Keep the frozen file and all existing forwards byte-for-byte untouched. Bind all structured state, conditions, units, provenance, references, validity envelopes, scenario assumptions, timing and numerical controls explicitly. The physical core can supply only defensible, provenance-carrying conversions; it is not already a drop-in source.
3. If a model-facing forecast consumer is approved, add a unique key/name and a new `Forward` branch in `crates/ignis-wsp/src/models.rs`, route `artifact` and a synthetic fixture to the adapter, and add a no-fit `Expert` in `experts()` only once its `PrefixBundle` mapping can actually be satisfied. `Expert::forecast` receives a `LoadedRelease`, prefix and settings and returns `AnalysisArtifact`; `fit` must refuse fitting. A host-derived scoped `WspModelService` must use the admitted prefix. Emit `liquid_diameter` in metres as `model_output`, retain `time_origin`, input/settings hashes, experimental state, assumptions, support/refusals and source provenance; do not invent calibrated uncertainty or silently transform the conditional reference into an observed flame. If required inputs cannot be expressed faithfully, return a typed refusal until the shared contract is reviewed and regenerated with its real producer/consumer.
4. Extend `crates/ignis-wsp/src/audit.rs` with an explicit source list including the actual kernel and every new adapter/dependency that influences the result. `forward_hash_of` panics for an unknown name, whereas `strict_route_check_of` currently uses an empty list for an unknown name and can report a misleading pass. Register and test source identity before relying on either. Include physical core only if the actual route uses it. Changing an adapter/source must change its forward identity; preserve existing model identities.
5. Use the established `Model::build_release` route with a real synthetic fixture and real strict-route check, then `assemble::save` to an appropriate isolated registry and reload. `ModelBuildManifest`/`ModelRelease::check_construction` require literal author/patch/hash, matching parent and tensor digest, strict profile, non-calibrated uncertainty, W0 independent exposure and no parent, `not_trained`, `experimental`, literal-authoring lineage and no posterior; registry save/load repeats construction and stored tensor checks. These mechanical checks are necessary, not scientific qualification. `assemble::build_release` itself **does not call** `spec.validate` or `patch.validate_against`; it records spec/patch checks as passed assuming the caller already materialized. Do not call it directly as a way around the blocker. Registry acceptance alone does not prove the forward ran or the spec was valid.

## Integration tests to require

- Frozen-byte hashes and canonical spec hash separately; singleton-bound contract acceptance, inverted-bound rejection, scalar coverage, exact π and canonical patch identity. Negative tests for missing, repeated, wrong-shape, out-of-range, nonfinite and unknown tensor ops; hash mismatch must refuse.
- Synthetic materialize -> actual forward-source identity -> fixture artifact -> isolated save/load -> exact tensor/manifest readback, with failed and missing fixture/strict checks distinguished. Ensure unknown forward names cannot obtain a passed audit, and changed executable forward or adapter changes the digest.
- Real producer -> scoped admitted prefix -> structured properties -> forward -> artifact; raw and SI values, locators, phase, dependency, reference, frames and time origin survive; absent, conflicting, unavailable-at-cutoff, wrong units/domains, mismatched components and provenance fail closed. No caller-supplied partition grants. Verify content/settings identity includes every input and numerical choice.
- Compare any adapter's liquid outputs and refusals against the untouched kernel on synthetic cases, including zero transport, condensation, mixture ordering, envelope mismatch, conservation, boundary crossing and convergence. Confirm no pre-existing forward or model result changes; never use test/holdout outcomes for these checks.
- Sheet reference remains separately labelled, no conversion to visible/UV diameter or ignition/extinction; no assumed or synthetic uncertainty represented as calibrated. Validate output units, support/refusal and an experimental unqualified state end to end.

# ignis-server

The runtime API (Axum + Tokio + Tower), started by `ignis serve`. Forecasts run **in process**: the
binary injects the experts (`Vec<Box<dyn Expert>>`); the server builds the causal `PrefixBundle` with
the expert's own prospective policy and runs `Expert::forecast` on one bounded Rayon pool through
`spawn_blocking`.

With `--dev`, a second, fully separate origin serves the synthetic development fixture under
`/api/fixtures/*` with its own synthetic expert (`fixture.synthetic_d2`). Fixture and registry data
are never mixed.

## Modules

`api` (routes, V3.1 §20.2) · `state` (origins, per-origin caches and jobs) · `refusal` (typed refusals:
`unsupported`, `insufficient_inference`, `invalid_request`, `not_found`, `precondition_failed`,
`unavailable`, `failed`) · `evidence` (read-only lexical FTS5 search over the catalog) · `fixture` (the
synthetic dev origin; data in `fixtures/`). The run-record registry (`ignis_core::records`) and the forecast
path with its write-once store (`ignis_core::analysis`) live in core and are shared with `ignis infer`.

## `/api/v1` (research runtime, task M2)

State in `--state-dir` (default `runs/server`): `state.sqlite` (SQLite WAL, `ignis-research`) and
`artifacts/` (content-addressed). Callers are identified by `--auth local` (one user) or
`--auth cloudflare-access` (identity from the Access header; only behind cloudflared). Each request gets
a host-derived research `ExecutionScope`: its own workspace, outcomes of `train` only, no code
execution. Errors are `ErrorEnvelope`. OpenAPI: `GET /api/v1/openapi.json` (generated by `aide`).

| Method and path | Contract |
|---|---|
| `GET /capabilities` | configured services, which C0 tools can run, and the agent runtime (`agent_runtime`, `runtime_build` manifest) |
| `POST /episodes` · `GET /episodes` · `GET /episodes/{id}` | `ResearchEpisode` (create is idempotent on `client_request_id`; model releases are verified, the corpus snapshot is pinned by the host) |
| `POST /episodes/{id}/messages` | appends `message.user` (idempotent); with the agent runtime, starts a turn for messages no turn has received |
| `POST /episodes/{id}/{pause,resume,cancel}` | `ResearchEpisode`; pause/cancel interrupt the running turn, resume reconciles it first; cancel also cancels the episode's jobs |
| `POST /episodes/{id}/approvals/{approval_id}` | `{"decision": "approved"\|"denied"}` for an `approval.requested`; approving needs the capability of the escalation's effect (`202`, `404` once resolved) |
| `GET /episodes/{id}/events?after=` | SSE of `ResearchEvent` (`id` = seq, resume with `Last-Event-ID`; `410` when the log does not cover the cursor) |
| `GET /artifacts/{id}?offset&len` · `?pointer=` · `/meta` | bytes · `InlinePayload` · `ArtifactRef` |
| `POST /search` · `GET /sources/{id}/pages/{page}` | `KnowledgeService` (`503 capability_unavailable` until configured) |
| `GET /models` · `GET /models/{id}` | `ModelService` |
| `POST /analyses` | `ForecastRequest` → `ToolResult` accepted + `JobRef`; output is an `AnalysisArtifact` artifact |
| `GET /jobs/{id}` · `POST /jobs/{id}/cancel` | `JobRef` (claimed interactive > evaluation > ingestion; lower classes capped) |
| `POST /uploads/initiate` → `PUT /uploads/{id}/content` → `POST /uploads/complete` | declared type/length/sha256 → bytes verified in staging → `ArtifactRef` (`--max-upload-bytes`) |

### Agent runtime (task M1)

`--codex-bin` (env `IGNIS_CODEX_BIN`) points at the native `codex` executable of the pinned release
(`ignis_research::runtime::PINNED_CODEX_VERSION`, today 0.169.0); `--codex-sha256` pins its hash,
`--codex-model` the model, and `--codex-login-home` (local development, `--auth local` only) a Codex home
signed in with a Codex account instead of an API key (`tools/codex/login.*`). At startup a preflight checks the version, hashes the binary, generates the
protocol schema from it (`app-server generate-json-schema`, hash in the build id) and probes the stdio
handshake. A missing or wrong binary leaves the runtime unavailable in `/capabilities`; the server still
runs and records messages. Without `--codex-bin` the runtime is not configured.

The bridge (`ignis_research::runtime::CodexBridge`) runs one `codex app-server --listen stdio://` per
workspace (`CODEX_HOME = <state-dir>/codex/ws-<hash>`, environment cleared except process essentials and
`CODEX_API_KEY`/`OPENAI_API_KEY`), one thread per episode, public profile only: no shell, no web search,
no browser/computer use, read-only sandbox, approvals to the host (shell and permission widening denied
by policy, file writes in the episode's scratch directory resolved through the endpoint above). Codex
items map to `message.delta`/`message.completed`, `tool.started`/`tool.finished`,
`approval.requested`/`approval.resolved` and `episode.status_changed`; anything else naming the thread
is archived as `runtime.opaque` with its payload in an artifact. Turns left open by a crash are settled
from the Codex thread at startup, never re-sent. No real model turn is run by the test suite.

Setting it up on a machine (find/install the pinned binary, start, send one message):
[`tools/codex/`](../../tools/codex/README.md).

With `--dev`, the same routes are also served at `/api/fixtures/v1` from the C0 contract fixtures
(`fixtures/contracts/`, everything `synthetic_fixture`, own state under `<state-dir>/dev-fixture`): each
workspace starts with the fixture episode, search/read return the fixture pages, models list the W0
release, and a forecast fails (the fixture has no forward).

The legacy routes below serve outcomes of `train` runs only (validation/test → `403 scope_denied`);
`/seal`, `/reveal` and `/admin/reload` work only with `--internal-routes` (always on the fixture origin; otherwise a typed `internal_route_disabled` refusal),
and every reveal attempt is appended to `runs/evaluation/reveal_log.jsonl`.

## Endpoints (under `/api`, each also under `/api/fixtures` in dev mode)

| Method and path | Purpose |
|---|---|
| `GET /health` | origin, registry counts and errors, experts, execution mode |
| `GET /experiments?family=&cohort=&split=&partition=&q=` | runs, filtered by family, cohort (id or 16+ hex prefix), split partition (`split` with `partition`) and text |
| `GET /cohorts` | cohorts with their frozen splits and run counts per partition |
| `GET /experiments/{id}` | full record, summary, control history, releases of the family |
| `GET /experiments/{id}/observations?cutoff_s=` | admitted observations and contours at the cutoff, pending ones (metadata), hidden count |
| `GET /experiments/{id}/series?cutoff_s=[&quantity=]` | admitted measurements as columns per (quantity, channel), for plotting |
| `GET /experiments/{id}/overlay?cutoff_s=` | BASS recordings of the run and the contours admitted at the cutoff |
| `GET /experiments/{id}/video/{file}` | a recording's bytes (byte ranges for seeking), for runs outside the validation/test partitions |
| `POST /compare` | condition table of 2-8 runs, with typed refusals of numeric comparison |
| `GET /models` | `experts` (one row per expert: `state`, `n_releases`, latest release, `has_candidate_model`) and `models` (every saved release) |
| `GET /models/{id}` | release with its tensor verification |
| `POST /forecast` | `{run_id, cutoff_s, model_release_id, settings?, wait_ms?}`: artifact, or a job id to poll |
| `GET /jobs/{id}`, `GET /analysis/{id}` | job state; a stored artifact with its context and seal |
| `POST /acquisition` | `{analysis_id, cost_per_observation?}`: candidate observations and their VOI scores |
| `POST /seal`, `POST /reveal` | hash commitment, then the continuation; reveal refuses without a seal, and refuses the test partition on the registry origin (`ignis eval reveal --final-test` is the only way) |
| `POST /evidence/search`, `POST /brief` | evidence retrieval; structured assembly without a language model |
| `POST /score/student-t`, `POST /admin/reload` | frozen kernel; reload the registry |

Forecast artifacts are stored write-once at `artifacts/analysis/<hex>/` (`artifact.json`,
`context.json`, `prefix.json`). `ignis infer forecast` writes the same files and the same artifact id as
`POST /forecast`. A BASS recording of a validation or test run is withheld (file and NASA link), since it
would show the sealed continuation. `/acquisition` scores through the injected `AcquisitionScorer` (the
`ignis` binary injects `ignis_train::decide::score_candidates`); experts with no candidate-measurement model
answer a typed `no_candidate_model`, and runs where every recorded observation is already admitted answer
`no_candidates`.

## Command

```bash
ignis serve [--dev] [--port 8787] [--host 127.0.0.1] [--data data/work/records] \
  [--cohorts data/work/cohorts] [--splits data/splits] [--raw-samples data/raw/samples] \
  [--artifacts artifacts] [--evidence-db artifacts/evidence/evidence.sqlite] [--compute-threads 2]
```

`--data` (env `IGNIS_RECORDS`) is the records directory (default `data/work/records`). A built web client in `web/dist` is served at `/` when present.

## Tests

```bash
cargo test --release -p ignis-server
```

`agent.rs`: the agent runtime against the fake app-server (`ignis-server-fake-codex`): capability status
for a missing/wrong/pinned binary, and one turn on the fixture episode (tool call, denied approval, SSE).
`fixture_flow.rs`: `forecast_seal_reveal_round_trip`, `acquisition_scoring_never_reads_hidden_values`,
`release_family_mismatch_is_a_typed_refusal`, `insufficient_prefix_is_refused_by_the_expert`; unit tests in
`api`, `evidence`, `fixture`. Forecast parity with the CLI: `crates/ignis-cli/tests/forecast_parity.rs`.
